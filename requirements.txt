# The host's dependencies, pinned to the interpreter this installation actually runs.
#
# Every line below carries a version. Until 2026-11-04 almost none of them did -- 242 of 249
# lines were a bare name -- and that is how a single pip run on 2026-11-03 downgraded
# scikit-learn to 1.7.2, below the range in which the retained estimators had ever been read,
# and moved pandas from 3.0.3 to 3.1.0, which removed a keyword the dataset reader depended on.
# Both were silent. Nothing in an install said a qualified version had been replaced.
#
# Two lines are ranges rather than pins, deliberately:
#
#   scikit-learn  a *measured* reader window for the retained estimators. 1.8.0 writes them;
#                 1.8.0 and 1.9.0 were compared against the real artifacts. The upper bound is
#                 the point of it, and tests/test_estimator_compatibility.py keeps one there.
#   pandas        3.1.0 is what the host runs; pytorch_env runs 3.0.3, and the dataset reader
#                 is verified on both. The range says both are supported; the pin would not.
#
# What is deliberately NOT here: the foundation model packages -- chronos, timesfm, tirex, the
# timecopilot family, tabpfn, gluonts, nixtla. The host carries every runtime *adapter* and no
# model package: eforecast/runtime_adapters refuses a method whose package is absent, which is
# what routes that work to the image that does carry it. Those live in
# docker/requirements-foundation.txt and docker/requirements-lagllama.txt.
#
# Minor versions break things here, so prefer changing one line and running the suite over
# re-freezing the file. pip, setuptools and wheel are left unpinned on purpose.
